OAAF online assessment

Rate what your AI system or agent can do, see which requirements apply, record what you find, and get a decision per capability using the fixed rules of the Operational AI Assurance Framework (OAAF) v1.0. Everything runs in your browser. Nothing is sent anywhere.

1. The system

Name the system as it is actually operated. Set a materiality threshold if your organisation has one. If it has none, any consequence that moves money, commits the organisation to a third party or communicates externally on its behalf counts as material.

2. Capabilities and the two-question test

A capability is something the system can cause to happen: approve a payment, send a reply, reorder a queue. For agents, treat each class of tool action as a capability. Rate each one with two questions.

Q1. Human acceptance. Must a human positively accept this specific output before it takes effect? Being able to see it, sampling outputs, or stepping in afterwards does not count.
Q2. Consequence. If the output is wrong, would the harm be irreversible before it would normally be detected, or exceed the materiality threshold? Judge the consequence, not the action: reordering a queue is reversible, the delay it causes is not.

3. Consequence Tier

The highest factor governs. A system with any High capability is at least Tier 2. Regulatory classification (for example EU AI Act high-risk status) is recorded separately and does not set the tier.

4. Requirements

Only the requirements that apply at this tier are shown. ◆ marks control-critical requirements: the ones needed to detect a problem and stop it. Prefer records of a control operating over documents describing it. A control owned by another team counts only if it is evidenced against this system.

5. Decision per capability

Findings are rated by rule. Any open Critical finding makes a capability Not Ready. There is no score: one missing stop mechanism is never averaged away.
